- Recommendation Registry: 53 columns (REGISTRY_COLUMNS)

Professional numeric economics
- Economic impact cells are numeric where available.
- Positive signed impact = savings.
- Negative signed impact = cost increase.
- Zero = known no change.
- UNAVAILABLE is never coerced to zero.
- Currency is explicit on each detailed economic grain.
- Impact type is explicit (SAVINGS / COST_INCREASE / MIXED / NO_CHANGE / UNAVAILABLE).
- No decorated strings such as "Save USD ..." or "Cost +USD ..." are used in economic numeric cells.
- Negative values use accounting-style parentheses/red number formatting.

Excel safety/readability
- Long numeric identifiers are written as explicit text cells with the Text number format, preventing scientific notation/precision loss (no apostrophe workaround).
- Rows 1-2: title/context.
- Row 3: section bands.
- Row 4: filterable headers.
- Identity columns and headers are frozen.
- Detailed sheets are Excel tables.
- Verbose audit JSON is placed at the far right and remains compact.
- No business formulas, hidden sheets, or macros.

Rendering
- Rendered with openpyxl (pip-installable); validated by tools/validate_workbook.py and tests/test_workbook_contract.py.
- Text that begins with '=' is forced to a text cell, so no cell can become a formula; audit cells over Excel's 32,767-character limit are truncated with a visible marker (none in the demo run).

Validation
- Exact ordered row keys are regression-tested against the contract-owned column declarations.
- Workbook projection contains no blank semantic values.
- Reporter JSON remains the authoritative source of truth.
