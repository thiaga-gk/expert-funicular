How this trace stays true

The end-to-end golden cases run the Publisher demo for the case's warehouse, store its package, then run the Realizer's live path against a simulated world in which the case's change happens at the stated time. The stored output is compared on every test run, and a deliberate change is regenerated with an approval message, so a behavior change in either product shows up as a reviewed diff here too.

python scripts/update_realizer_e2e_goldens.py --check                 # report drift, write nothing
python scripts/update_realizer_e2e_goldens.py --approved-change "<why>" --stage all --case ge12-full-scope-auto-stop

Check yourself
The owner applied only step 1. Why is the realized saving compared with the auto-stop candidate's range rather than the scenario's total?

The scenario total includes the size canary, which was not applied. An exactly applied single step is judged against its own candidate's isolated savings; the denominator source in this package is {{rpkg:economics.denominator_source}}.

The annualized saving is above the published high. Why is it still REALIZED and not flagged for review?

A result at or above the published low is realized. Review is flagged only above {{fact:realizer.review_above_high}} times the high ({{cite:src/realizer/estimator/economics.py::REVIEW_ABOVE_HIGH}}; {{ex:realizer.review_line}} here), which this saving does not reach. The replay is the optimistic track of the published range, so landing near the high end is expected.

Why does the measured window start the day after the change instead of at the change time?

Billing settles by whole UTC days. The change day mixes two configurations, so it belongs to neither window; the pre and post windows are whole settled days of one configuration each.

What would make the claim OBSERVABLE_ONLY even though the saving is real?

Any hard disqualifier: another knob changed in the window, a failed financial-quality gate, a cross-check that disagrees, an open canary window or another lineage owning the change. The saving is still recorded; it just cannot be claimed for this recommendation.
