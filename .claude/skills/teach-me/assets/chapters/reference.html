How this guide is built and refreshed

This page is generated by the teach-me skill in .claude/skills/teach-me/. Its facts (versions, thresholds, constants, flags, tables, the worked example) are imported from the code and the reference documents each time it is built; its narrative comes from chapter fragments that cite the code they explain. Do not edit the HTML: change a fragment or the generator and rebuild.

/teach-me

Builds the guide if it is missing; otherwise reports whether it is current and offers a refresh. /teach-me <topic> answers a question in chat from the matching chapter without rebuilding.

/teach-me refresh

Finds the chapters whose cited source files changed, re-reads that code, rewrites only those chapters, rebuilds and verifies.

python .claude/skills/teach-me/scripts/build_guide.py --stale    # chapters whose cited sources changed
python .claude/skills/teach-me/scripts/build_guide.py --verify   # rebuild, then check citations, examples, links
python .claude/skills/teach-me/scripts/build_guide.py --check    # does the committed page equal a fresh build?

Each chapter's cited files are fingerprinted into the page, which is how --stale knows what changed. --verify fails when a cited file or symbol has moved, when a worked-example figure no longer matches the golden case, or when the page would load anything from the network. The test suite also checks that every citation in the committed page still exists ({{cite:tests/test_docs.py}}).

You renamed a function this guide cites. What fails, and how do you fix it?

build_guide.py --verify and the citation test in tests/test_docs.py fail. Run /teach-me refresh: the chapter citing the renamed symbol is stale, and its rewrite updates the citation.

The guide and a reference document disagree about a threshold's value. Which is right?

Neither is the authority: the value comes from the Thresholds dataclass in code. The guide's tables are generated from it, so a mismatch means the reference document is stale (and its test should fail).
