# Databricks product constants

Documented SQL warehouse behavior and limits the publisher relies on. They describe the platform, not policy: no cost profile or policy version changes them, and they live in `src/publisher/config/defaults.py` (`PRODUCT_CONSTANTS`), not in `Thresholds`. A test compares each row with the code. When Databricks changes one of these, the constant changes with a policy version bump and golden updates. Policy defaults are in [thresholds.md](thresholds.md).

| Constant | Value | Meaning | Source |
|---|---|---|---|
| `SCALE_UP_LAG_MINUTES_PRO_CLASSIC` | `5` | Minutes before a Pro/Classic warehouse adds clusters for queued demand: the busy-period start window and the idle minutes that separate busy periods (minimum-cluster floor target, concurrency collector). | [SQL warehouse sizing, scaling and queuing](https://docs.databricks.com/aws/en/compute/sql-warehouse/warehouse-behavior) |
| `SCALE_UP_LAG_MINUTES_SERVERLESS` | `1` | The same window for Serverless warehouses, which scale up within about a minute. | [SQL warehouse sizing, scaling and queuing](https://docs.databricks.com/aws/en/compute/sql-warehouse/warehouse-behavior) |
| `QUERIES_PER_CLUSTER_PRO_CLASSIC` | `10` | Concurrent queries one Pro/Classic cluster serves (documented scaling rule); peak demand in queries becomes clusters at this rate for the max-cluster target and the max-cluster cost model. | [SQL warehouse sizing, scaling and queuing](https://docs.databricks.com/aws/en/compute/sql-warehouse/warehouse-behavior) |
| `AUTO_STOP_FLOOR_PRO_CLASSIC` | `10` | Lowest auto-stop (minutes) evaluated for Pro and Classic warehouses; the reviewer rejects a changed Pro/Classic auto-stop below it. | [Create a SQL warehouse](https://docs.databricks.com/aws/en/compute/sql-warehouse/create) |
| `AUTO_STOP_FLOOR_SERVERLESS` | `5` | Lowest auto-stop (minutes) evaluated for standard Serverless warehouses; a lower value set through the API is left alone. | [Create a SQL warehouse](https://docs.databricks.com/aws/en/compute/sql-warehouse/create) |
| `AUTO_STOP_MAX_MINUTES` | `1440` | Highest auto-stop (minutes) evaluated; the running-idle collector measures every `auto_stop_step_minutes` step from the lower floor up to it. | [Warehouses API: create](https://docs.databricks.com/api/workspace/warehouses/create) |
| `MAX_CLUSTERS_SUPPORTED_LIMIT` | `40` | Largest max-cluster value (clusters) the platform accepts: an increase at this ceiling is blocked (`MAX_CLUSTER_LIMIT_REACHED`), a larger demand-derived target is capped (`PEAK_DEMAND_ABOVE_CLUSTER_LIMIT`), and the reviewer and the JSON Schema reject anything above it. | [Warehouses API: create](https://docs.databricks.com/api/workspace/warehouses/create) |
| `MIN_CLUSTERS_SUPPORTED_LIMIT` | `30` | Largest min-cluster value (clusters) the platform accepts; the reviewer and the JSON Schema reject anything above it. | [Warehouses API: create](https://docs.databricks.com/api/workspace/warehouses/create) |
