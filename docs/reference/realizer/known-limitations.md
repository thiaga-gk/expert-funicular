# Realizer Known Limitations

This file records limitations that remain true in the current Realizer release (component version 1.0.0). Resolved implementation gaps are intentionally not retained here. The Publisher's own limitations are in [`../publisher/known-limitations.md`](../publisher/known-limitations.md).

## Not yet possible

1. **Input contract:** the Realizer accepts only Publisher packages with Reporter JSON Contract `contract_version` 1.0.0 (`validate_package_shape` in `src/realizer/config/loader.py`). The current Publisher writes the later contract in [`contracts/shared/reporter-json-contract.md`](../../contracts/shared/reporter-json-contract.md), so a package from today's Publisher cannot be realized. A 3.x adapter, a semantic change reviewed on its own, is needed before any real use. The 1.0.0 contract code (`contracts/reporter_contract.py`, `contracts/reporter_schema.py`) is readable from the git tag `realizer-reorg-oracle-1.0.0`, under `legacy/realizer_single_file/`: `git show "realizer-reorg-oracle-1.0.0:legacy/realizer_single_file/contracts/reporter_contract.py"`.
2. **No live collector:** the engine takes a normalized post-change observation ([`source-evidence-contract.md`](../../contracts/realizer/source-evidence-contract.md)), replayed from a file (`--observation`) or generated as the synthetic demo (`--demo`, `--demo-modified`). `collector.py` holds only `load_observation` and `demo_observation`; nothing reads a system table or an API.
3. **No live source-system end-to-end run:** the Realizer has never been run against a connected Databricks workspace, and there is no integration test of collector SQL, source schema or a full run against configured source systems. A real run needs limitations 1 and 2 resolved first.
4. **No `.xlsx` workbook writer:** the single-file release rendered a Realizer workbook extension with the `artifact_tool` runtime and the retired Workbook v1.1.0 reporter, and that renderer is not part of this repository. The workbook projection (the rows a renderer would draw, [`workbook-compatibility-contract.md`](../../contracts/realizer/workbook-compatibility-contract.md)) remains in `src/realizer/contracts/report.py`.
5. **Realization levels are not implemented:** the step, plan and package realization levels ([`repo-reorg-design.md`](../../architecture/realizer/repo-reorg-design.md) section 10) do not exist. The measurement per application episode (candidate or scenario scope) is the closest thing; inventing the levels would be new behavior.
6. **Reviewer checks are not implemented:** the reviewer checks of design section 11 (evidence completeness, lifecycle, baseline, attribution, overlap, no double count, annualization, consistency) are not implemented as checks that can reject. The Reviewer assembles what the single-file release decided.

## Original behavior kept for parity

The Realizer was extracted from the single-file release with identical outputs, and the behaviors below were found on the way and deliberately not changed, because a fix alters stored outputs and decisions. Each is a candidate for a separately reviewed change that regenerates the stored scenarios. The detail of each, with the phase that found it, is in [`repo-reorg-parity.md`](../../proposals/realizer/repo-reorg-parity.md).

7. **Billing restatement reprocessed:** reprocessing a billing-restatement observation once more appends a second `BILLING_CORRECTION_RECORDED` entry whose `corrects_entry_id` is the restated measurement itself, and the snapshot's `correction_count` goes from 1 to 2; a further pass adds nothing. Every other scenario is idempotent on its last observation. The `restatement-reprocessed` scenario pins the current behavior.
8. **Unrelated step recorded as an application:** an authority-eligible step whose observed value is unrelated to the recommendation (for example an unknown warehouse size) is recorded as `APPLICATION_OBSERVED` although it never becomes the active application. The snapshot then counts it as an applied application with conformance `UNRELATED`, and later runs treat it as the previous application.
9. **Raw package value in `compare_step`:** `compare_step` (`src/realizer/reconciler/matching.py`) compares the normalized observed value with the package's raw value, so a package value with different spelling or spacing matches differently than its normalized form would.
10. **Correction type spelling:** the measurement's `correction_status` is the observation's raw correction type (`ORIGINAL` when absent, the spelling as given otherwise), while the `BILLING_CORRECTION_RECORDED` payload upper-cases the type and defaults it to `RESTATEMENT`.
11. **Counterfactual id hashes the raw window start:** the counterfactual id hashes the observation's `window_start_utc` as given, while the validation and measurement ids fall back to the applied time when it is absent. An observation without a window start therefore hashes a missing value (null) there, not the applied time.
12. **Non-text origin maps to `UNKNOWN`:** `attribution_result` (`src/realizer/estimator/attribution.py`) turns an origin that cannot be converted to text into `UNKNOWN`, because its enum fallback also catches the conversion's error.
13. **Redundant readiness and gate fallbacks:** on the realize path `calculate_economics` re-evaluates readiness, which is always ready there, and `attribution_result` always receives the quality gates, so its own gate fallback is reached only by direct calls. Nothing observable changes; the code stays as it was.
14. **Cost increase reads as under-realized:** a cost increase is classified as under-realized with re-optimization recommended and a negative ratio, and a claimable one is attributed as negative savings.
15. **Failure ordering around the ledger:** `realize` reads the ledger before it records the lineage entry and then overwrites the result, so only the read's failure is observable: a corrupt ledger raises before the lineage entry exists, while a malformed observation raises after it.
16. **Duplicate entries still rewrite files:** a repeated entry is suppressed by id on each append, so a run that records an event an earlier run (or an earlier slot) already recorded logs `ledger.duplicate_suppressed` and still rewrites its evidence and regeneration files with the same content.
17. **Replay cuts that match no entry:** a replay cut (`--replay-through`) before every entry raises `cannot project empty ledger` after the events were recorded, and a cut that is not a time raises after them too; neither writes the package or the snapshot file.
18. **Log time label:** the CLI's log format labels local time as `Z` (`src/realizer/common/logging.py`), and an uncaught failure gives a traceback with exit status 1.
19. **Product version in provenance:** `PRODUCT_VERSION` (`src/realizer/config/settings.py`) is the hard-coded string `2.8.0` of the release the single-file Realizer shipped in. It is written into ledger-entry and realization-package provenance and is not the current Publisher version; changing it changes the stored outputs.
